# PDLP against the simplex and HiGHS, and the compiler's ceiling -- 2026-09-24

`python -m bench.pdlp --sizes ... --time-limit 120` (queue R1, roadmap Phase 14).
A transport problem, n sources x n sinks, n^2 decisions and 2n^2 nonzeros,
solved in a sandboxed child under the run's memory ceiling (4096 MB), as a
run does. Generating and compiling are timed apart from the solve.

**Verdict: `solve.pdlp` stays off; the large-scale threshold is 1,000,000
nonzeros** (`app.solve.pdlp.LARGE_SCALE_NNZ`, down from the roadmap's 10^7,
which no model fits under the memory ceiling). What the rows say:

- **Up to 500,000 nonzeros PDLP buys nothing.** GLOP, HiGHS and PDLP solve in
  the same seconds; PDLP's objective is within 2e-6 of the proven one.
- **At 2,000,000 nonzeros HiGHS runs out of memory**, GLOP proves the optimum
  in 54 s and PDLP answers in 38 s, 3e-8 from it. PDLP's place starts here --
  but GLOP still *proves* its answer in under a minute, and trading a proof
  for 30 % is not a default. A problem that wants it turns `solve.pdlp` on.
- **At 4,500,000 nonzeros every solver runs out of memory**, PDLP included:
  the ceiling holds the compiled model and the solver's copy together. Past
  this size the platform needs more memory per solve (`SOLVE_MEMORY_MB`), not
  another method.

**The compiler was the ceiling, and it was a defect.** The first run (below,
before) spent 213 s compiling 250,000 decisions, and the time grew as
n^1.5. A profile put 14.9 of a 15.6 s compile in symmetry detection
(`app.solve.symmetry.classes`), which ran on every compile -- the setting is
off -- and scanned every parameter cell for every set member. Bucketing the
cells and edges by member once (`_by_member`) made it linear: 213 s -> 4.7 s,
14 s -> 0.7 s at 40,000 decisions, identical classes on five families
(`tests/test_symmetry.py`). The rows after the fix are the second table.
